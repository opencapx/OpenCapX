# Changelog

## 0.1.1 — 2026-09-23

- **Bubble position lifecycle fixed** — the saved side is now applied at startup instead of on the first per-second poll tick (a non-default side showed the wrong layout for a second, then the window visibly jumped); changing pet size under a "bottom" layout recomputes the window height (the bubble used to be clipped when the pet grew, dead space when it shrank); the pet rect is read after the compositor settles, so the side-switch anchor no longer computes from a stale viewport; and when the pet sits close enough to a monitor edge that the bubble's full budget would cross it, the side mirrors automatically — the pet stays put, only the bubble moves. A new **gap** setting (0–24px) spaces the bubble off the pet, and side layouts scroll like the vertical ones always did (an ask box could outgrow the window, and clipping it hid choices the user had to click).

- **Two new bubble themes, a focus mode, localized phrases** — **manga** (heavy black outline, hard offset shadow, speed-line texture on near-white paper) and **blueprint** (cyanotype sheet, white two-axis grid, dashed outline) join the set; the **focus** mode promotes the single most urgent session (a waiting one outranks a working one) and counts the rest below the row instead of rotating through everyone like carousel; persona phrases were hardcoded English and now carry i18n keys for all 12 themes × 4 states × 3 languages; the mode picker gained localized labels instead of raw option ids.

- **Bubble settings hardened** — number inputs (max rows / bubble duration / break minutes) clamp to the same bounds the overlay enforces instead of saving raw input (a typed 999 displayed as 999 while behaving as 10), `load()` normalizes values written by older builds or hand-edited files, and the theme row gets its own label and a full-width stacked row instead of reusing the app-theme "Theme" key and crushing its hint.

- **Show Bubble tray toggle** — `bubbleEnabled` is reachable from the tray menu like Show Pet; the overlay polls the settings file, so the change lands within one tick.

- **Factory Droid, Cursor and Copilot CLI write-back** — the command rules now rewrite those hosts' shell calls too: Factory Droid and Copilot CLI take the Claude shape (`PreToolUse` + `hookSpecificOutput.updatedInput`; Copilot CLI needs the PascalCase event, and its rewritten commands still pass its own confirmation dialog — upstream github/copilot-cli#2643), while Cursor takes its top-level envelope (`permission` + `updated_input`, `{}` on the no-decision path). The remaining pass-through hosts (windsurf / antigravity / kiro / grok / pi) keep event-only integration.

- **Oh My Pi (omp) host support** — `opencapx connect omp` installs an OMP extension that reports session state and applies command-rule rewrites to Bash tool calls: it asks the hook per `tool_call` and returns the reply as `{ input }`, so the replacement lands before OMP's approval gate and the prompt shows what actually runs. Registered as a rewrite host like Claude Code / Codex / Gemini; `connect` also writes the MCP entry (`~/.omp/agent/mcp.json`, identity pinned with `OPEN_CAPX_AGENT` so the MCP child and the hooks agree on the agent) — omp can drive capabilities, not just hooks — and the generated extension is refreshed on `connect` when the template changes.

- **Stable CLI path for agent configs** — hooks and MCP entries written by `opencapx connect` now point at `~/.opencapx/bin/opencapx` (a stable copy of the running binary) instead of the binary's current location. A moved or cleaned dev checkout, or an app reinstall, no longer leaves agents firing a dead path: the shim is refreshed at app start, at `connect`, and on every hook invocation, and existing configs still referencing an older binary path are rewritten in place (fixes release installs firing a stale `target/debug/opencapx`).
- **Session-start capability injection** — the SessionStart hook now injects a capability digest into the agent's context (Claude Code, Codex, Factory Droid, Grok Build), so a fresh session knows what OpenCapX can do without calling `list_capabilities` first. Same data source, capped at 60 entries / 4 KiB, opt-out in Settings → General, fails open, audited as `session.context.injected`. See [docs/mcp.md](docs/mcp.md) "Session-start capability injection".
- **Danger guard: `curl … | sh` runs in the sandbox** — the rule engine refuses compound input by design, which left the classic download-and-execute idiom untouched. A built-in whole-line rewrite now splits it: the download stays on the host (it needs the network) and the execution runs under `opencapx sandbox --profile installer` — installer-compatible (network open, `$HOME` writable) but with a curated deny list that keeps **secret material unreadable** (`~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.npmrc`, `~/.docker/config.json`, `~/.kube`, `~/.git-credentials`, `~/.config/gcloud`, `~/.azure`, browser profiles, Keychains, shell history, …) and **persistence hot spots unwritable** (shell rc files, `~/.gitconfig`, `~/Library/LaunchAgents`, cron/at, …). Covers `curl|wget … | sh|bash|zsh|dash|ksh` — normalized first, so `env`/`env -i`/assignment leads, backslash quotes (`\curl`) and path-prefixed downloaders (`/usr/bin/curl … | sh`) no longer slip through — plus `bash <(curl …)`, `sh -c "$(curl …)"` and `eval "$(curl …)"`. The download lands in a `mktemp` path (the fixed predictable name + curl's symlink-following was a local write-anywhere race) and the rewrite cleans up after itself while propagating the real exit code. User rules still win; hits are audited as `danger/*`. Shapes that match but cannot be rewritten safely (stdin/interactive/positional shell operands, `wget -qO-`, output flags) and idioms embedded in compound lines (`cd /tmp && curl … | sh`) are **audited without rewriting and without an auto-allow writeback** — the host's own permission flow still decides (`danger/unsupported-shape`, `danger/embedded-download-execute`); downloader variants (`wget2`/`axel`/`xh`/`aria2c`) are visible that way too. Disabling the guard does not silence it: matched idioms are audited as `danger/guard-disabled`. The stance is durable config: `opencapx guard mode <installer|strict|off>` and `opencapx guard env <strip|keep|clear>` write `~/.opencapx/guard.json` (0600, case-insensitive values), `OPEN_CAPX_DANGER_GUARD` still overrides per-invocation. `opencapx guard trust <domain>` passes that host through untouched, audited as `danger/trusted-passthrough` — trust requires **every URL in the line** to be trusted, so a decoy trusted token cannot vouch for an untrusted payload (redirect chains remain text-invisible). Deliberately conservative (bails on `sudo`/`doas`, nested substitutions) and stricter on failure — a failed download no longer executes anything. See [docs/rules.md](docs/rules.md) "Danger Guard".
- **`opencapx sandbox` (executor pack v1)** — runs a command behind the platform's OS guard: macOS seatbelt (`sandbox-exec`) and Linux bubblewrap (`bwrap`); other platforms warn once and run unguarded (W1 — a microVM tier via microsandbox is the planned strong option for Windows). Default policy **denies the network** and keeps the filesystem read-only except a per-run scratch dir and the child's `TMPDIR`; `--rw <dir>`, `--allow-net`, `--timeout <secs>` and `--check` are the explicit opt-outs. `--profile installer` is honored on **both** backends now: Linux expresses the deny list as shadowing mounts — tmpfs over directories, a read-only `/dev/null` bind over file targets (a tmpfs is a directory; mounting one over a file would error bwrap into the unguarded fallback; existing paths only, so creating a previously absent `~/.zshrc` stays possible on Linux — seatbelt denies creation too). **Timeouts kill the whole process group** (the child runs as its own group leader; before, only the direct child died and grandchildren survived); normal exits still let installers leave services running. **Environment filtering at the spawn point** (seatbelt/bwrap cannot express it, the runner can): `--env strip` (default) drops secret-looking variables (`*_TOKEN*`, `*SECRET*`, `*PASSWORD*`, `*CREDENTIAL*`, `*_API_KEY`, `SSH_AUTH_SOCK`, `GIT_ASKPASS`, …) — with installer mode's open network this closes the cheapest exfiltration path; `--env clear` whitelists the bare minimum, `--env keep` opts out. Fail-open by design: a missing or broken backend never blocks the command, **and such a run is audited as `sandbox.unguarded`** (reason included) so the Activity Timeline shows the fence was absent; exit code / stdout / stderr pass through untouched. The seatbelt profile shares the calibrated plugin-sandbox shape in `core/sandbox.rs`, now with `/dev/null` + `/dev/fd` write exemptions so `> /dev/null` and process substitution keep working — a strictly-more-permissive change to the plugin profile as well (`process*` + `mach-lookup` + global reads remain the known trade-off; the boundary is write + network). This is a fence against accidental damage and common malware behavior (persistence + egress), not a proof-grade boundary against directed attackers.
