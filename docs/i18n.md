# Internationalization (i18n)

Three layers of copy, each with a clear owner. **The cost of adding a language ≈ translating one JSON file**.

## 1. Where the Copy Lives

| Layer | Location | Does adding a language require code changes? |
|---|---|---|
| Frontend UI (settings page, bubbles, notification center, …) | `src/locales/<code>.json` | No (auto-discovered) |
| Language endonym (the name shown in the dropdown) | `src/locales/locales.json` | No (auto-registered by the scaffolder script) |
| Native UI (tray menu / icon tooltip / system notifications) | `src-tauri/src/core/i18n.rs` | Yes: add a `Strings` constant + a `Lang` branch (~15 lines) |
| Agent display name (`claude` → `Claude Code`) | `AGENTS` in `src-tauri/src/hooks.rs` | Not translated (product name) |

The reason native copy does not share the JSON: the tray/notifications are needed when there is **no WebView**, or even before the window has been created,
so they cannot read the frontend's i18n. The volume is tiny (a dozen or so strings), and it uses struct fields rather than key lookups — so a typo is a compile-time error.

## 2. Adding a Language (3 Steps)

```bash
# 1) Generate the locale pack: filled with English (usable immediately; missing translations show English) + auto-register the endonym
npm run i18n:scaffold -- fr --name "Français"

# 2) Translate the values in src/locales/fr.json (do not touch the keys)

# 3) Validate: the key set and placeholders must exactly match en
npm run i18n:check          # mismatch → exit code 1 (CI/build will block it)
npm run i18n:report         # also shows how many entries are still untranslated (value identical to English)
```

To make the **tray and notifications** speak this language too, also add in `src-tauri/src/core/i18n.rs`:

```rust
pub const FR: Strings = Strings { show_pet: "Afficher l’animal", ..EN };

// and add a branch in each of from_locale / strings
```

The language dropdown and `availableLocales()` are both auto-discovered; the settings page needs no changes.

## 3. Validation Rules (scripts/i18n-check.mjs)

- **The key set must exactly match `en.json`**: a missing key or an extra key is a failure.
- **Placeholders must match**: if `en` has `{text}`, the translation must also contain `{text}` (otherwise runtime arguments cannot be substituted).
- **`locales.json` must register the endonym**, otherwise the settings page displays the language code.
- `npm run build` runs `i18n:check` first, so drift cannot enter the build output.

## 4. Conventions

- `src/locales/en.json` is the **single source of truth**; key names use camelCase (`petPackHint`, `tabAudit`).
- **Do not hardcode user-visible copy in code**; if there is no key, first add one to en.json and then translate it.
- When adding/changing a key, change all three languages together; the "untranslated" count in `i18n:report` means the value is identical to English, which may be
  a genuinely identical form (such as `open`), so it only reports and does not fail the build.
