# OpenCapX plugin template

One tag flow: edit the manifest → push a `v*` tag → GitHub Actions automatically packs + signs + pre-runs the auto-gate + attaches the release asset (`.ocplugin`).

## Quick start

1. Edit `opencapx-plugin.json`:
   - Change `id` to your reverse-DNS domain (e.g. `com.yourname.my-plugin`; **cannot be changed after publishing** — the id is the plugin's identity)
   - `name` / `description` / `author` / `license`
   - `capabilities` / `permissions`: use built-in names (see `docs/capability.md`) or declare a new-domain capability
     in object form in this manifest (see `docs/permission-domains.md`)
2. Implement `bin/plugin.py` (based on `opencapx_sdk`; the template already has the `image.analyze` placeholder)
3. Local self-test (after building the CLI at the OpenCapX repo root):
   ```bash
   opencapx pack . --key <your-seed-hex> --key-id <your-keyId> --out dist/plugin.ocplugin
   opencapx verify-package dist/plugin.ocplugin   # F10 auto-gate pre-run
   ```
4. Configure in the repo Secrets: `OCX_SIGNING_KEY` (64-hex seed, generated by `opencapx keygen`), `OCX_KEY_ID`
5. Push a tag (`git tag v0.1.0 && git push --tags`) → the release automatically produces a signed `.ocplugin`

## Parameters (declarative settings `settings[]`)

The template's `opencapx-plugin.json` already ships a working `settings[]` block (5 entries): `response_prefix` (text, with `required` / `maxLength`), `detail_level` (dropdown, **structured options**), `include_notice` (toggle), `notice` (with a `visible` predicate, `aliases`, and a `LocalizedText` label), `api_token` (secret, no `default`). The settings page renders a graphical form from it — no longer an empty `{}` JSON input box.

The template also demonstrates three presentation-layer fields (they do not affect storage or `config.*` reads/writes):

- **Structured options**: `options` may mix bare strings with `{"value": "...", "label": {...}}` — `label` is localized and used only for display, while what is stored in config and compared by predicates is always `value` (see `detail_level`);
- **`order`**: form display order, smaller first, undeclared entries fall back to manifest order (all 5 template entries set it; `api_token` is deliberately last);
- **`deprecated`**: `{"en": "...", "zh-Hans": "..."}` deprecation note — the control stays usable, with a "deprecated" marker and reason on the row.

The corresponding user-side behavior: edited entries automatically carry a "modified" marker and can be **reset to default** in one click; for a plugin that declares nothing, the settings page degrades to a key-value editor and states "see the README for meaning" — that is the entire reason to declare `settings[]` (the standard layering of declarative settings). The `list` type (a plugin-owned add/delete/edit/reorder list) is covered in `docs/plugin-authoring.md` §5.

Editing this block is editing the settings page; `bin/plugin.py` re-reads it with `config_get` **on every capability call** (see `_setting` / `_setting_str`), so a save takes effect on the next call with no plugin restart. On the plugin side, a secret is read with `secret:<key>` and its value is never echoed back. Installation statically validates: every `default` must satisfy the `validate[]` of its own declaration, and every key referenced by `visible` must already be declared.

Full references (this README does not copy the field tables):

- `docs/plugin-authoring.md` §5 "Giving it parameters (declarative settings settings[])" — choosing controls by purpose, `LocalizedText`, predicates, validation rules, and how to read at runtime;
- `docs/plugin-manifest.md` "Declarative settings (settings[])" — the frozen schema, 12 control types, and two install-time static checks.

## Keys

- The private seed **goes only in GitHub Secrets**, never into the repo; losing it = you can no longer publish updates under the same key
  (the client will confirm with a "new publisher" warning, see D4/D5).
- After the public key + keyId generated by `opencapx keygen` are submitted to the registry (`publishers[]`) and approved,
  the client will show "registry verified".
